Self-Hosting

Homelab

Zu Hause betreibe ich im Kleinen, was ich beruflich im Großen mache: Dienste, die reproduzierbar ausgerollt, überwacht und abgesichert werden. Zwei Knoten, alles in Docker Compose, alles in Git – kein Container läuft, der nicht in einem Commit steht.

Diese Seite zeigt, wie die Teile zusammenhängen, und vor allem, warum sie so zusammenhängen. Die meisten Entscheidungen hier sind Antworten auf eine konkrete Frage: Was passiert, wenn dieser Teil kompromittiert wird oder still ausfällt?

Topologie

Ein kleiner Rand, ein großer Speicher.

Die Arbeit ist auf zwei Geräte verteilt. Der Raspberry Pi ist der Rand des Netzes: Nur er nimmt Verbindungen aus dem Internet an, terminiert TLS, entscheidet über Sperren und beobachtet alles andere. Das NAS trägt die Last – Medien, Dateien, Bücher, CI – und ist von außen nie direkt erreichbar. Auf seiner Hardware läuft Proxmox als Hypervisor, die Docker-Dienste in einer schlichten Debian-VM darüber.

Der Router leitet genau zwei Ports weiter, 80 und 443, beide auf Traefik. Von dort gehen Anfragen über das LAN an die Dienste auf dem NAS.

Drei Eingänge, eine Grenze

Ein Host(…)-Filter hält niemanden draußen – der Port schon.

Traefik lauscht auf mehreren Entrypoints, und die Grenze zwischen öffentlich und privat verläuft zwischen ihnen, nicht zwischen Hostnamen. Den Host-Header wählt der Client selbst; jeder Router auf :443 ist deshalb öffentlich, egal auf welchen Namen er hört. Grafana, Prometheus, Alertmanager und die Jenkins-Oberfläche liegen darum auf einem eigenen Entrypoint, :8443, den der Router nicht weiterleitet – zusätzlich hinter Basic Auth.

Beide Sicherungen sind so gebaut, dass sie im Zweifel schließen: Der interne Entrypoint ist der Standard, auf dem neue Router landen, wenn niemand etwas anderes sagt. Und die CrowdSec-Middleware hängt am öffentlichen Entrypoint selbst statt an einzelnen Routern – ein später hinzugefügter Dienst ist geschützt, ohne dass jemand an ein Label denken muss.

Kein Docker-Socket in Traefik

Traefik beantwortet das Internet und führt in jeder Anfrage ein Plugin aus. Mit gemountetem Socket wäre Codeausführung dort gleich root auf dem Pi. Stattdessen spricht es mit einem socket-proxy, der nur Container auflisten und Events lesen darf – in einem Netz ohne Route nach draußen.

CrowdSec, erst geprobt

CrowdSec liest Traefiks JSON-Access-Log, ein Bouncer-Plugin in Traefik setzt die Sperren durch. Scharf geschaltet habe ich es erst, nachdem zwei Wochen Log (rund 710 000 Zeilen) durch dieselben Szenarien gelaufen waren: 271 Sperren, alle auf Cloud- und Hosting-Netzen, kein einziger echter Client.

Jenkins nur als Webhook

Jenkins hält den SSH-Schlüssel für beide Knoten – wer Jenkins kontrolliert, ist root im ganzen Homelab. Öffentlich ist deshalb genau ein Pfad, der GitHub-Webhook. Alles andere auf diesem Host beantwortet Traefik mit 404, bevor es Jenkins erreicht.

Vom Commit zum Container

Git ist die einzige Quelle; niemand ruft auf den Knoten docker compose up von Hand auf.

Jeder Dienst ist ein Verzeichnis mit einer Compose-Datei. Ein Push auf main löst über den Webhook die Pipeline aus: Sie prüft alle Compose-Dateien, spiegelt das Repository per rsync auf beide Knoten, schreibt die Secrets aus den Jenkins-Credentials in .env-Dateien und rollt nur die Stacks neu aus, deren Verzeichnis sich geändert hat. Danach prüft ein Skript, dass jeder Container läuft, gesund ist und nicht in einer Neustart-Schleife hängt.

„Geändert“ heißt dabei: seit dem letzten erfolgreichen Build, nicht seit dem letzten Commit. Sonst verschwinden die Änderungen eines gescheiterten Deploys stillschweigend, sobald der nächste Commit einen anderen Dienst betrifft.

Renovate hält die Tags aktuell

Jedes Image ist auf eine Version festgelegt, damit Git immer sagt, was läuft. Minor-, Patch- und Digest-Updates committet Renovate nachts gesammelt direkt auf main; Major-Updates kommen als Pull Request. Releases, die jünger als drei Tage sind, bleiben liegen – was am ersten Tag zurückgezogen wird, erreicht die Knoten nie.

Jenkins aktualisiert sich selbst

Ein Job kann den Controller, auf dem er läuft, nicht neu starten. Er übergibt deshalb zuletzt an ein Skript auf dem NAS: Jenkins stoppen, jenkins_home sichern, neue Images umtaggen, starten und prüfen – Login, Plugins, beide Agents. Scheitert ein Punkt, rollt das Skript selbstständig zurück.

Plugins als Code

Die komplette Plugin-Liste des Controllers steht versioniert im Repository, und Renovate hebt sie in einem Commit an – Plugins geben Mindestversionen voneinander an. Ein Test mit einer echten Plugin-Erhöhung hat gezeigt, dass das ohne eine bestimmte Entrypoint-Variable stillschweigend nichts bewirkt.

Monitoring

Ein laufender Container ist noch kein funktionierender Dienst.

Prometheus, Grafana und Alertmanager laufen auf dem Pi und beobachten beide Knoten: node-exporter für den Host, cAdvisor für die Container, dazu Traefiks eigene Metriken. Der blackbox-exporter ruft die öffentlichen URLs von außen ab und fängt damit, was ein gesunder Container nicht verrät – eine kaputte Route oder ein abgelaufenes Zertifikat. Selbst der Jenkins-Webhook wird geprüft: Die Probe erwartet Jenkins' eigenes 405, denn eine Route, die nicht mehr passt, würde Traefik mit 404 beantworten.

Die Aufbewahrung ist auf 15 Tage und 4 GB begrenzt, das Scrape-Intervall auf 30 Sekunden: Der Pi bootet von einer SD-Karte, und eine Zeitreihendatenbank ist der schnellste Weg, eine zu verschleißen.

Alarme für das stille Versagen

Die gefährlichsten Ausfälle sehen gesund aus: CrowdSec liest weiter, parst aber nichts mehr; der Bouncer fragt keine Sperren mehr ab und lässt dann alles durch. Für genau diese Fälle gibt es eigene Regeln – sonst sähe „niemand gesperrt“ genauso aus wie „Schutz kaputt“.

Fünf Dashboards, provisioniert

Host-Zustand, Container und Dienste, Traefik-Anfragen und Sicherheit, Steckdosen mit Stromkosten pro Tag und CrowdSec. Alle liegen als JSON im Repository und erscheinen auf einer frischen Grafana-Instanz ohne Import.

Was nicht im Code steht

Eine Firewall-Regel, Logrotate, CrowdSec-Pfade: Einiges lebt auf den Hosts statt in einer Compose-Datei. Es ist im README festgehalten – samt dem Grund, warum es nicht anders geht –, weil sich sonst beim Neuaufsetzen niemand daran erinnert.
